# ADR-0051: Los paquetes se publican en ESM, y un proyecto CommonJS los carga con `require`

- **Estado:** propuesta. Mientras no se acepte, rige [ADR-0015](./0015-plataforma-y-ci.md) completo
- **Reemplaza:** "los paquetes son solo ESM" de [ADR-0015](./0015-plataforma-y-ci.md), solo en lo que toca a quién los puede cargar. El build sigue siendo solo ESM, y el resto de ese ADR sigue vigente.
- **Drivers:** un consumidor de la 1.0.0 reportó el 2026-11-09 que, porque su proyecto es CommonJS, tuvo que hacer el binario `.mjs`. `require('@runa-cmd/core')` falla con `ERR_PACKAGE_PATH_NOT_EXPORTED`, porque `exports` declara solo la condición `"import"`. El mismo `dist` sí carga con `require` desde Node 22.12 (`require(esm)`), y `engines` exige `>=24.0.0`: se observó en Node 24.13 y 26.11, también con el Zod de CommonJS armando los schemas, y convierte y rechaza valores igual que desde ESM. Entre las alternativas de [la comparación](../../guides/runa-compared.md), commander 15.1, yargs 18.2, citty 0.2 y cac 7.1 son solo ESM y cargan con `require`, y oclif publica CommonJS: Runa es la única de las seis que un proyecto CommonJS no puede cargar.
- **Decisión:** cada entrada de `exports` de los paquetes publicados declara `"default"` en vez de `"import"`, con `"types"` primero. No hay un segundo build. Ningún módulo publicado usa `await` de nivel superior, porque eso rompe `require` con `ERR_REQUIRE_ASYNC_MODULE`, y una prueba en CI hace `require` de cada entrada de cada paquete. Con Node, `import` y `require` reciben la misma instancia del módulo, así que no hay dos copias de `core`.
- **Alternativas descartadas:** dejarlo como está obliga a un proyecto CommonJS a usar `.mjs` o `import()`, sin un motivo técnico, porque el `dist` ya carga. Publicar también un build CommonJS duplica el build y el peso, y si un proyecto carga las dos copias quedan dos `core`: `instanceof CommandError` falla y hooks y plugins se reparten entre ellas. Ese costo solo se justificaba cuando Node no podía cargar ESM con `require`, y con `engines >=24` puede.
- **Costo aceptado:** ningún módulo publicado, ni de Runa ni de una dependencia en runtime, puede usar `await` de nivel superior; si hiciera falta, sería una major. Quitar `"default"` también sería una major. Hasta verificarlo, no se sabe si TypeScript acepta los tipos en un proyecto CommonJS con todas las versiones y modos de `module`.
- **Revisar si:** algo que solo se puede hacer con `await` de nivel superior llega a un módulo publicado, o una versión de Node soportada vuelve a necesitar una flag para `require(esm)`.
- **Código:** `packages/core/package.json`, `packages/help/package.json`, `packages/mcp/package.json`, `packages/completions/package.json`
